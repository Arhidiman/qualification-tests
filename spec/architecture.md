# 🏗 Архитектура приложения

## 1. Общий подход

Приложение использует **простую архитектуру без строгого модульного деления**.

Цель:

* минимальная сложность
* быстрая разработка
* предсказуемая генерация кода AI

Без:

* feature-sliced design
* domain-driven design
* сложных слоёв абстракции

---

## 2. Структура проекта

```
src/
  app/
    providers/
    store/
    data/

  pages/
    Main/
    Test/
    Results/

  components/
    Header/
    TestCard/
    QuestionBlock/
    Pagination/

  libs/
```

---

## 3. Описание папок

### 📁 app/

Глобальный уровень приложения.

#### providers/

Глобальные провайдеры:

* Zustand provider
* Ant Design Theme provider
* другие глобальные обёртки

---

#### store/

Глобальное состояние:

* Zustand store
* бизнес-логика тестов
* управление попытками

---

#### data/

Статические данные:

* JSON-файлы тестов

---

### 📁 pages/

Страницы (уровень роутинга).

#### Main/

* выбор теста
* отображение списка тестов

---

#### Test/

* отображение вопросов
* управление ответами
* пагинация
* завершение теста

---

#### Results/

* история попыток
* статистика

---

### 📁 components/

UI-компоненты:

* переиспользуемые элементы интерфейса

Примеры:

* Header
* TestCard
* QuestionBlock
* Pagination

---

### 📁 libs/

Глобальные утилиты:

* работа с Local Storage
* helper-функции
* форматирование

---

## 4. Правила архитектуры

### 🔁 Однонаправленный поток данных

* Pages → Components
* Components не импортируют Pages
* Store используется как единый источник состояния

Допускается:

* использование функций из libs везде
* ограниченное использование вспомогательных функций между слоями

---

### 🚫 Запрещено

* циркулярные импорты
* двусторонние зависимости между слоями

---

### 🧠 Логика

* Pages:

  * минимум логики или её отсутствие
  * только orchestration

* Components:

  * UI + локальная логика

* Store:

  * основная бизнес-логика

---

### 📄 Ограничения на файлы

Каждый компонент (и в pages, и в components) содержит максимум:

* 1 файл `.tsx`
* 1 файл `.scss` (опционально)

Пример:

```
TestCard/
  TestCard.tsx
  TestCard.scss
```

Без:

* index.ts
* hooks.ts рядом
* utils.ts рядом

---

## 5. Поток данных

1. Пользователь выбирает тест (Main)
2. Загружается JSON из app/data
3. TestPage отображает вопросы
4. Ответы сохраняются в store
5. При завершении:

   * считается результат
   * сохраняется в Local Storage
6. ResultsPage отображает статистику

---

## 6. Хранение данных

* тесты → JSON (app/data)
* состояние → Zustand store
* история → Local Storage

---

## 7. Принципы

* простота > идеальная архитектура
* плоская структура
* минимум абстракций
* код должен быть предсказуем для AI
